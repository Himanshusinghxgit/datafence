┌───────────────────────────────────────────────────────────────────────────┐
│                          POLICY STRUCTURE                                 │
└───────────────────────────────────────────────────────────────────────────┘

    policies.yaml
    │
    ├─ policies:
    │  │
    │  ├─ Policy 1: Customer Service Agent
    │  │  ├─ actor: "agent:customer_service"
    │  │  ├─ resource: "customers"
    │  │  ├─ operation: "read"
    │  │  ├─ effect: "allow"
    │  │  │
    │  │  ├─ field_restrictions:
    │  │  │  ├─ allow:  [id, name, email, phone]
    │  │  │  ├─ redact: [ssn, date_of_birth]
    │  │  │  └─ deny:   [credit_card, password]
    │  │  │
    │  │  └─ row_restrictions:
    │  │     ├─ tenant_id = context.actor.tenant_id
    │  │     └─ status = 'active'
    │  │
    │  └─ Policy 2: Block Write Operations
    │     ├─ actor: "agent:*"
    │     ├─ operation: "update"
    │     └─ effect: "deny"
    │
    ├─ pii_patterns:
    │  ├─ SSN: \d{3}-\d{2}-\d{4}
    │  ├─ Credit Card: \d{4} \d{4} \d{4} \d{4}
    │  └─ Email: [...]@[...].[...]
    │
    └─ sql_firewall:
       ├─ block_patterns:
       │  ├─ DROP TABLE
       │  ├─ DELETE FROM
       │  └─ SQL comments
       └─ allowed_operations: [SELECT, INSERT, UPDATE]


┌───────────────────────────────────────────────────────────────────────────┐
│                      SECURITY PROTECTION LAYERS                           │
└───────────────────────────────────────────────────────────────────────────┘

    Layer 1: Authorization
    ──────────────────────────────────────────
    ✓ Who is making the request?
    ✓ Are they allowed?
    ✓ Tenant match?

    Layer 2: Resource Validation
    ──────────────────────────────────────────
    ✓ Does resource exist?
    ✓ What operations are allowed?
    ✓ Any special restrictions?

    Layer 3: Field-Level Security
    ──────────────────────────────────────────
    ✓ Which columns can be accessed?
    ✓ Which should be redacted?
    ✓ Which are completely blocked?

    Layer 4: Row-Level Security
    ──────────────────────────────────────────
    ✓ Tenant isolation (tenant_id)
    ✓ Custom filters (status, etc.)
    ✓ Context-based filtering

    Layer 5: SQL Firewall
    ──────────────────────────────────────────
    ✓ Block SQL injection
    ✓ Block dangerous operations
    ✓ Validate query structure

    Layer 6: PII Detection
    ──────────────────────────────────────────
    ✓ Detect sensitive patterns
    ✓ Apply redaction strategies
    ✓ Prevent data leakage

    Layer 7: Result Validation
    ──────────────────────────────────────────
    ✓ Verify returned data
    ✓ Generate evidence
    ✓ Create audit trail

└───────────────────────────────────────────────────────────────────────────┘

    Test 1: Normal Query
    ─────────────────────────────────────
    Input:  "Show me customer information"
    LLM:    Query customers table
    Policy: ✓ Allowed
    Result: Returns id, name, email (allowed)
            Redacts ssn (sensitive)
    Status: ✅ PASS

    Test 2: Unauthorized Field
    ─────────────────────────────────────
    Input:  "Show credit card numbers"
    LLM:    Query credit_card field
    Policy: ✗ Denied (blocked field)
    Result: Field not included
    Status: ✅ PASS (blocked correctly)

    Test 3: SQL Injection
    ─────────────────────────────────────
    Input:  "users WHERE 1=1; DROP TABLE"
    LLM:    Passes malicious query
    Policy: ✗ SQL Firewall blocks
    Result: Request denied
    Status: ✅ PASS (attack prevented)

    Test 4: Cross-Tenant Access
    ─────────────────────────────────────
    Input:  Query with tenant_id: "other"
    LLM:    Tries to access other tenant
    Policy: ✗ Row filter enforces tenant
    Result: Only own tenant data
    Status: ✅ PASS (isolation works)

    Test 5: PII Redaction
    ─────────────────────────────────────
    Input:  Query includes SSN field
    LLM:    Requests SSN
    Policy: ⚠ Allow but redact
    Result: SSN shows as ***-**-****
    Status: ✅ PASS (PII protected)


┌───────────────────────────────────────────────────────────────────────────┐
│                        INSTALLATION STEPS                                 │
└───────────────────────────────────────────────────────────────────────────┘

    Step 1: Install Dependencies
    ════════════════════════════════════
    $ pip install datafence langflow

    Step 2: Copy Component
    ════════════════════════════════════
    $ mkdir -p ~/.langflow/components
    $ cp src/datafence/integrations/langflow_component.py \
         ~/.langflow/components/

    Step 3: Start Langflow
    ════════════════════════════════════
    $ langflow run
    # Opens http://localhost:7860

    Step 4: Import Example
    ════════════════════════════════════
    In Langflow UI:
    1. Click "Import Flow"
    2. Select: examples/langflow/customer_service_bot.json
    3. Configure settings
    4. Test!
