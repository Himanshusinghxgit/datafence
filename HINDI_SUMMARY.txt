🎯 KYA BANAYA HAI?
==================

DataFence ek security system hai jo AI agents (jaise ChatGPT, Claude) ko 
enterprise data access karne se pehle check karta hai. 

SIMPLE ANALOGY: Jaise bank mein security guard check karta hai ki kaun andar 
ja sakta hai aur kya dekh sakta hai - waise hi DataFence check karta hai ki 
AI agent kaunsa data access kar sakta hai.


📋 PROBLEM JO SOLVE KIYA
=========================

1. AI models PROBABILISTIC hote hain - kabhi galti kar sakte hain
2. Wrong data access ho sakta hai
3. SQL injection attacks ho sakte hain
4. Sensitive data (like credit card, SSN) leak ho sakta hai
5. Multi-tenant apps mein ek tenant doosre ka data dekh sakta hai

DataFence DETERMINISTIC security boundary hai - chahe AI kuch bhi propose kare,
DataFence sirf authorized access hi allow karega.


🏗️ ARCHITECTURE (5 PHASES)
===========================

PHASE 1: CORE SECURITY (Foundation)
------------------------------------
✅ Policy Engine - YAML files mein rules likhte ho
✅ Column-level security - Kaunse fields dekh sakte ho
✅ Row-level security - Kaunsi rows dekh sakte ho (tenant isolation)
✅ Operation control - Read/Write/Update/Delete permissions
✅ Audit logging - Har request ka record
✅ Connectors: Memory, SQLite

Example Policy:
```yaml
resources:
  transactions:
    operations:
      allow: [read]
      deny: [delete]
    fields:
      allow: [id, amount, merchant]
      deny: [card_number, cvv]
    row_filters:
      tenant_id: "{{ actor.tenant_id }}"
```

PHASE 2: ADVANCED SECURITY
---------------------------
✅ SQL Firewall - SQL injection block karta hai
✅ PII Detection - Email, phone, SSN, credit card detect karta hai
✅ PII Redaction - Sensitive data mask/token/hash kar deta hai
   - MASK: ***-**-1234
   - TOKEN: [REDACTED_SSN]
   - HASH: sha256(value)
✅ Defense in depth - Multiple security layers

PHASE 3: PRODUCTION CONNECTORS
-------------------------------
✅ PostgreSQL - Connection pooling, prepared statements
✅ Amazon Athena - S3 data lake queries
✅ Snowflake - Cloud data warehouse
✅ Configuration - Environment variables, YAML files, connection strings

💻 KAISE USE KARTE HAIN?

1. BASIC USAGE (Python)
-----------------------
```python
from datafence import DataFence
from datafence.connectors import PostgreSQLConnector

# Setup
connector = PostgreSQLConnector(
    host="localhost",
    database="mydb",
    user="myuser",
    password="mypassword"
)

fence = DataFence.from_yaml("policy.yaml", connector)

# Request execute karo
result = fence.execute({
    "actor": {
        "id": "user:123",
        "tenant_id": "acme"
    },
    "operation": "read",
    "resource": "transactions",
    "fields": ["id", "amount", "merchant"],
    "filters": {"customer_id": "123"},
    "limit": 10
})

# Result check karo
if result.verified:
    print(f"✓ Allowed: {len(result.data)} rows returned")
    for row in result.data:
        print(row)
else:
    print(f"✗ Denied: {result.decision.reasons}")
```

🔄 FLOW KAISE KAAM KARTA HAI?
==============================

Step-by-Step:

1. User puuchta hai:
   "Show me John Doe's account information"

2. LLM (GPT-4) samajhta hai aur database query propose karta hai:
   Resource: customers
   Fields: id, name, email, ssn, credit_card
   Filters: name = "John Doe"

3. DataFence Security Component check karta hai:
   ✅ Authorization: Is actor allowed?
   ✅ Fields: Which fields are allowed?
      - Allow: id, name, email
      - Redact: ssn (***-**-****)
      - Block: credit_card (not allowed at all)
   ✅ Row filters: Add tenant_id, status filters
   ✅ SQL Firewall: No SQL injection
   ✅ PII Detection: Detect sensitive data

4. Database execute karta hai (only allowed query):
   SELECT id, name, email, ssn
   FROM customers
   WHERE name = 'John Doe'
     AND tenant_id = 'acme'
     AND status = 'active'

5. DataFence result validate karta hai:
   - SSN redact: "123-45-6789" → "***-**-****"
   - Credit card removed (wasn't allowed anyway)
   - Audit log create
   - Evidence generate

6. User ko safe response milta hai:
   "John Doe's account is active. Email: john@example.com"
   (SSN redacted, credit card blocked)

🎯 USE CASES
============

1. CUSTOMER SERVICE BOT
   Problem: Agent ko customer data chahiye but SSN/credit card nahi dekhna
   Solution: DataFence allows only safe fields, redacts sensitive data

2. MULTI-TENANT SAAS
   Problem: Har tenant apna hi data dekhe, doosre ka nahi
   Solution: Row-level filtering automatic tenant_id se

3. ANALYTICS BOT
   Problem: Aggregated insights chahiye but raw PII nahi
   Solution: Allow COUNT/SUM/AVG, block individual customer data

4. READ-ONLY AGENT
   Problem: Query to kar sake but data modify na kare
   Solution: Allow only "read" operation, block insert/update/delete
